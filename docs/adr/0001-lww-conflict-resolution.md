# ADR-0001：同步冲突采用后写覆盖（LWW）

- 状态：已接受
- 日期：2026-08-07

## 背景

离线优先同步下，同一篇日记条目可能在两处（手机本地、服务器）被独立修改。需要定义冲突解决规则。

## 决策

采用后写覆盖（Last-Write-Wins）：以客户端生成的修改时间为准，较新者胜出，旧版本直接丢弃，不做任何合并。

## 后果

- 优点：实现与行为完全可预期；无合并算法复杂度；与增量同步、墓碑机制天然契合。
- 缺点：同一篇条目在两台设备同时编辑时，一方的修改会整体丢失（概率极低，单用户场景可接受）。
- 明确不做：文本级自动合并（如 Git 式三方合并）、冲突双副本保留。

## 备选方案

- **自动合并**：日记不是协作文档，合并结果不可预期，复杂度不成比例。
- **冲突双份**：需要引入"冲突条目"概念与人工裁决流程，破坏"一篇条目一条记录"的模型。
