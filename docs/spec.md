# 规格：安卓日记软件（服务器同步版）

> 依据 CONTEXT.md 术语表与三次 ADR 综合而成。领域词汇以 CONTEXT.md 为准。

## Problem statement

用户需要一款安卓端日记应用，日记数据保存在自己的常开 Linux 服务器上。市面日记应用多为云服务托管（数据不在自己手里），或离线应用无备份能力（换机/丢机即丢数据）。本应用要求：**离线可写可看，联网自动与自托管服务器同步，换机可完整恢复**。

## Solution

双端架构：

- **安卓客户端**（Kotlin + Jetpack Compose）：本地完整数据副本（Room SQLite + 图片文件），离线优先。编辑、浏览、检索全部本地完成；同步在"打开 App 时 + 保存后"触发，通过 HTTP API 与服务器交换增量变更。
- **服务器**（Go + SQLite + 图片文件目录）：持有一份完整副本，提供变更流与图片存取 API，受 API Token 保护。

同步语义（贯穿双端）：日记条目由客户端生成 UUID 与同步时间戳；冲突按**后写覆盖**；删除为**软删除墓碑**；首次连接执行**全量拉取**作为增量基线，之后只交换增量。

## 接缝（Seams）

测试与实现的边界，规格按此组织：

1. **同步引擎**：藏起"增量拉取、后写覆盖合并、墓碑应用、变更推送、失败重试"全部逻辑，暴露最小接口（如 `sync(): SyncResult`）。客户端与服务器各有实现，语义由本文档约束。
2. **同步协议契约**：客户端 ↔ 服务器 HTTP API 的请求/响应形状，以契约测试锁定两端一致。

## User stories

### 条目管理
1. 用户可新建日记条目，必填正文，标题可选；保存时自动生成 UUID 与同步时间戳。
2. 用户可编辑已有日记条目（标题/正文/心情/天气/日记日期）。
3. 用户可删除日记条目——软删除，生成墓碑（条目 ID + 删除时间戳）。
4. 用户可在编辑页底部工具栏插入图片，图片插入于正文光标处，逻辑上属于正文的一部分。
5. 用户可在编辑页为条目设置心情（圆形图标行点选，可选值如 开心/难过）。
6. 用户可在编辑页为条目设置天气（圆形图标行点选，可选值如 晴/雨）。
7. 用户可在编辑页通过翻页日期选择器将日记日期补写到任意一天；日记日期独立于同步时间戳。
8. 用户在编辑页保存时，客户端对新增图片执行压缩（最长边约 2000px、JPEG 质量约 85%），压缩版为唯一版本，原图不保留。
9. 用户在编辑页保存后立即触发一次同步。

### 浏览与检索
10. 列表页按日记日期倒序展示条目，每条显示首图缩略图 + 标题/正文摘要 + 日期。
11. 日历页为月视图，有日记条目的日期打点；点击日期进入当天的日记条目列表。
12. 列表页顶部搜索按钮进入全文搜索：关键词匹配标题与正文文字部分，图片内容不参与。
13. 详情页为阅读视图：大标题、心情图标、图片大图、正文；操作含编辑、删除、导出为图片。

### 我的与设置
14. 我的页展示统计概览（总篇数、连续天数、心情分布等）与数据管理（导出、存储占用等）。
15. 设置页可配置服务器地址与 API Token；可查看同步状态。
16. 外观采用 Material You 动态取色 + 自动深浅色模式。

### 同步
17. 打开 App 时触发一次同步；同步成功后服务器与本地数据一致（以同步时间戳为准）。
18. 离线时全部编辑功能可用；联网后一次同步把离线期间的变更推送到服务器。
19. 同一篇日记条目在两端都被修改时，按同步时间戳较新者胜出（后写覆盖），旧版本丢弃。
20. 已删除条目在服务器端保持墓碑，不会因换机恢复或增量同步而复活。
21. 新设备首次配置（服务器地址 + Token）时执行一次全量拉取，之后转为增量同步。
22. 图片以文件形式独立传输与存储；传输失败可重试，不阻塞条目文本同步。
23. 删除条目时其图片文件一并清理（双端）。

## Implementation decisions

- 单用户，无账号系统。（Q1）
- 日记条目字段：标题、正文（图片内嵌）、日记日期、心情、天气、同步时间戳；不含标签。（Q2/Q22/Q23）
- 离线优先：客户端本地持有完整数据副本。（Q3）
- 标识与同步时间戳由客户端生成（UUID + 手机本地时间），服务器不分配。（Q4）
- 冲突解决：后写覆盖，不做合并。（ADR-0001）
- 删除：软删除墓碑。（Q6）
- 同步：增量；换机恢复以全量拉取为基线。（Q9/Q17）
- 图片外置：正文以标记引用图片，二进制独立传输存储，逻辑上属正文。（Q8）
- 同步时机：打开 App + 保存后；无常驻后台同步。（Q14）
- 图片压缩：最长边约 2000px、JPEG 约 85%，压缩版唯一。（ADR-0003）
- 数据加密：明文存储，不做 E2EE；HTTPS + API Token 保护。（ADR-0002）
- 双端互为备份，不额外做服务器侧备份脚本。（Q19）
- 服务器：Go + SQLite，自托管 Linux。（Q10/Q7）
- 客户端：Kotlin + Jetpack Compose。（Q12）
- 导航：底部四 Tab 日记/日历/我的/设置。（Q20-22）
- 详情页与编辑页分离；编辑页布局按 Q23 敲定。（Q23/Q24）
- 外观：Material You 动态取色 + 自动深浅色。（Q25）

## Testing decisions

- **同步引擎单测**（双端各自实现）：以伪造网络/存储层驱动，覆盖：增量拉取、LWW 冲突、墓碑应用与不复活、首次全量基线、失败重试、图片独立重试。
- **协议契约测试**：请求/响应形状（条目字段、墓碑标记、图片引用标记、变更流分页）锁定客户端与服务器一致。
- 服务器 HTTP 集成测试（httptest/SQLite 内存库）：Token 校验、变更流接口、图片上传下载、墓碑持久化。
- 客户端仓储与图片流水线以常规单测覆盖（压缩尺寸、缩略图、Room 查询、全文搜索）。

## Out of scope

- 标签字段（已否决）
- 端到端加密（ADR-0002 已否决）
- 常驻后台同步
- iOS/跨平台（已否决）
- 多用户/账号系统
- 服务器侧备份脚本（双端互为备份，ADR-0001 决策项之外）
- 富文本格式（纯文本 + 图片）
- 音频/视频、定位

## Further notes

- 待定实现细节：心情/天气具体取值集合、时间戳图标行为（正文插入当前日期时间）、导出为图片的格式与分享方式、同步协议端点设计、全文搜索实现方式（SQLite FTS）。
- 换机恢复流程需在设置页给出清晰引导（输入地址 + Token → 全量拉取）。
- 服务器部署文档（systemd 服务、HTTPS 证书）随服务器代码交付。
